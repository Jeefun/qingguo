# 鸿蒙与 Android 业务对齐复核

复核日期：2026-11-21  
核对基线：`Xanerix/guoapp` 正式 Release `app-v2.0.2-114`（`2.0.2+114`，commit `5dcb127`）。Android 上游 `main` 的 `2.0.3+115` 是后续开发日志，不并入这次正式发布基线；Android UI/硬件专属行为亦不直接算作鸿蒙业务要求。来源：[正式发布说明](https://github.com/Xanerix/guoapp/releases)、[上游更新日志](https://github.com/Xanerix/guoapp/blob/main/CHANGELOG.md)。

## 已实现的主要业务主链

鸿蒙版已有发现/分类分页、普通搜索、详情和分集、追剧/待看、历史与单用户本地偏好、站源切换、播放器线路/清晰度/弹幕/断点续播。内置多个站源与在线站源商店的 `categories → catalogPage → search → detail → resolveMedia` 基础链路已接通。最近加入官方系列数据的分季入口、季间独立进度及自动跨季；红果取流也已适配 V5，并有 H.265 回退逻辑。

这些核心链路有实际业务代码；这不等于下载、备份、真实排行榜或上游模块的全部可选接口也已移植。

## 确认的业务缺口

| 优先级 | 功能 | 当前证据与用户影响 |
|---|---|---|
| P0 | 离线下载/已下载管理 | 没有下载页、任务服务、路由或本地视频播放数据流。`QgAppSettings` 中残留 `downloadWifiOnly/downloadParallel` 字段不产生下载功能；上游具备分集下载及已下载内容管理。用户不能离线看剧。 |
| P0 | 备份与恢复 | `entry/src/main/ets/entrybackupability/EntryBackupAbility.ets` 的 `onBackup/onRestore` 只写日志，不读写应用数据；设置页也没有完整导出/导入。用户不能将追剧、观看记录、设置、搜索记录及站源模块状态作为备份迁移。 |
| P1 | 多用户/权限 | 当前 `QgStore` 持有一份全局状态，没有用户配置、密码切换、来源访问 ACL 或按用户隔离的观看/追剧数据。若目标是完整对齐 Android 用户体系，这是架构级功能，不能用“青果影迷”静态标签代替。 |
| P1 | 真实在线排行榜 | `ExploreTab.ets` 的 `rankedList()` 只把当前目录列表（排除首张大卡）按本地 `heat` 排序后取五项；“换一批”继续加载普通目录下一页。它不是红果真实榜单，也没有多榜类型入口。上游红果模块 1.0.6 manifest 实际声明总榜、真人剧榜、漫剧榜、AI 剧榜，但鸿蒙 `QgSource/QgRepository/QgModuleSource` 无排行榜调用接口。 |
| P1 | 站源可选能力运行时 | `QgModuleStore.ets` 接受 `account/suggestions/recommendations/danmaku/devices/rankings` 等 capability；通用 `QgSource`、`QgModuleSource`、Repository/UI 只消费普通目录/搜索/详情/播放和分季等少数接口。安装成功或清单声明某能力，不代表鸿蒙端可在页面中使用该能力。真实榜单为已确认示例；账号、设备等需分别设计对应的 ArkUI/平台业务，不能宣称已支持。 |
| P1 | 追剧更新管理 | 当前片单展示本地追剧/待看记录，但没有上游完整的检查更新、未看集数/新集标记、按站源筛选和批量管理流程。用户需要逐条打开详情才能确认更新。 |
| P1 | 投屏/后台媒体控制 | 没有 DLNA 设备发现、投屏会话或投屏播放控制服务，也没有锁屏/通知媒体会话。Android 2.0.2+114 列有投屏媒体服务；鸿蒙可行实现需单独适配 HarmonyOS 后台能力，不应把“普通播放器能播”算作投屏已对齐。 |
| P1 | 红果听书/小说 | 内置 `HongguoSource.GENRES` 目前只有短剧、漫剧、AI 剧等分类；分季逻辑会把 `book-*` 视为非分季并返回空。内置路径没有连通听书分类、章节详情和专用章节播放。红果的在线 JS 模块则提供 audio categories/detail/play，因此用户额外安装兼容模块后可能有更多功能，但不是开箱即用的内置能力；还需验证系统播放器对音频媒体的行为。 |
| P2 | 直接点击播放的手机流程 | `ExploreTab.goDetail()` 对卡片固定推入详情页；上游 2.0.2+114 手机行为是直接播放，剧集加载失败时才显示详情。详情页仍可作为明确入口；这一项是默认点击流程差异。 |
| P2 | 搜索联想 | 红果源包含联想数据，但 `QgSource` 没有通用 suggestions 契约，`QgModuleSource` 也不调用联想接口；`SearchPage` 只展示本地历史/静态热门词。输入时没有站源联想结果。 |
| P2 | 详情纠错反馈 | `DetailPage.reportIssue()` 当前只提示“已记录”，没有持久化或真实提交，属于误导性的占位功能。 |
| P2 | 部分内置站源无法在线播放 | `SoraniSource.play()` 明确说明滑块登录播放未支持；`HeitaoSource` 对当前未支持的地址加密方式抛出错误。它们可以有目录/搜索，但不能据此承诺全站播放都已对齐。 |

## 本轮验证

重新运行 `node scripts/run-tests.cjs`，14 项电脑端回归脚本通过，覆盖站源模块存储/隔离/宿主/激活、红果播放与设备注册、播放器重试、分季数据及页面逻辑。它们验证已存在的主链，**不验证上述缺口已实现**，也不等同于设备端 HTTP/Video/N-API/后台服务实测。1.1.1 此次未改生产代码、未运行新的 HarmonyOS 构建或真机测试。

## 建议的补齐顺序

1. 先落实用户和数据兼容边界，再设计持久化备份包；用户/权限与备份格式会影响追剧、历史和模块状态的存储结构。
2. 再做下载队列与已下载媒体：持久化任务状态、断点/失败恢复、网络限制、并发、存储选择、音视频/CENC 转换和本地播放必须作为一个完整闭环。
3. 建统一的模块可选能力契约，再接红果多排行榜、联想、推荐与设备等；未消费的 capability 不应被描述为已支持。
4. 确认手机点剧交互约定、追剧更新检查/筛选及投屏/后台媒体能力的 HarmonyOS 平台方案。
5. 清除“反馈已记录”之类假成功提示；只列出在实际设备/网络上可完成的内置站源能力。

这份复核是差异清单，不是已完成 Android 全业务移植的声明。
